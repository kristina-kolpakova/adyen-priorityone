## Known limitations

- **Account priority is the single highest-scoring open opportunity.** Each account's score is its best deal's `PriorityScore` (value + quarter + stage); accounts with the same score are ranked by that deal's amount. Other open opportunities don't affect the ranking, so an account with several live deals scores the same as one with only its best deal. Because `PriorityScore` can only take a few values (10–90), many accounts share a score and the amount tie-break does much of the ordering (today six accounts score 90).
- **Tie-break for equal opportunity scores is undecided.** When two opportunities in the same account have the same `PriorityScore`, it's not yet decided whether the larger deal or the sooner-closing deal should rank first. For now, ties are broken by CSV row order (`rank(method="first")`), which is deterministic but has no business reason behind it. This only changes an account's score when its top two opportunities tie and close in different quarters.
- **In the Renewal and Upsell/New scores, every additional opportunity counts, and deal size has limited weight.** These two scores are shown for context and no longer set the account's priority. Each extra opportunity adds a share of its `PriorityScore` (50% current quarter or overdue, 25% next quarter, 10% later). Because stage and timing make up most of `PriorityScore`, a small deal can add as much as a large one: Marlowe's €45K deal adds 30 points, while Kestrel's €1.23M future deal adds 6. No cap on additional opportunities is applied yet; this will be revisited after Gong signals are added.
- **Scores depend on the date the script runs.** Scoring uses today's date (`pd.Timestamp.today()`), by design, so priorities stay current. The mock data, however, is a snapshot from mid-November 2026: as time passes, more deals show as overdue, and from 1 January the current quarter becomes Q1 2027, so quarter scores and the ranking shift. Score checks that expect fixed totals (e.g. Krakatoa = 90) will fail after the quarter changes. Automated scoring tests will need a controllable reference date.
